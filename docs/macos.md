# macOS

Raymond installs a root launchd daemon (`dev.raymond`), dedicated `lo0` aliases and one marked `/etc/resolver/<zone>` file per zone. Existing resolver files are never overwritten. Only aliases absent during installation are recorded for later removal. At service startup, missing recorded aliases are recreated after reboot. The daemon runs as root to bind ports 53/80 and restore aliases; this is a documented v0.1 privilege tradeoff. Future privilege isolation is required before broader deployment.

Use the explicit [installation walkthrough](installation.md) and [README service setup commands](../README.md#install-and-enable-os-integration). macOS uses launchd rather than systemd. `sudo ./bin/raymond install` accepts the reviewed executable owned by the invoking user and copies it to `/Library/PrivilegedHelperTools/dev.raymond`, outside Homebrew-managed `/usr/local`. This managed daemon and its ancestor directories must be root-owned and not group/world writable; the user checkout needs no ownership changes. The default wildcard policy is checked before creating OS resources; the opt-in HTTP coexistence policy below still requires successful exact-address binds after alias setup. macOS's standard `/etc` and `/var` aliases to `/private` are recognized; other symlinks are rejected.

Installation does not start the launchd daemon immediately. `sudo ./bin/raymond start` bootstraps it; RunAtLoad enables reboot startup. Stop boots it out and restart kickstarts it. Uninstall removes only resources whose hashes match the root-owned journal and aliases created by Raymond. The system log `/var/log/raymond.log` is retained.

Native acceptance passes on macOS 15/arm64: installed archives without Go on PATH, OS DNS resolution, localhost:80 coexistence, launchd crash/restart recovery, alias reconstruction after deleting owned aliases while stopped, refusal of modified files, and safe uninstall. A Seatbelt sandbox blocks non-localhost outbound connections during the offline runtime test. Kernel socket inspection verifies exactly the dedicated TCP/UDP listeners. Full machine power-cycle and other macOS versions/architectures have not been exercised.

Darwin can allow a wildcard socket and a specific-address socket to coexist under SO_REUSEADDR. By default, `doctor` conservatively rejects wildcard listeners using macOS's built-in `/usr/sbin/lsof`. Explicitly setting `proxy.allow_wildcard_coexistence: true` permits HTTP coexistence while retaining exact TCP/UDP bind checks and the DNS wildcard guard. It does not terminate other services or change Docker configuration. High-port tests on the local Mac verified independent HTTP responses on two loopback addresses, including Docker-first and native-listener-first startup orders. On the local macOS 27/arm64 Mac, the user-installed daemon subsequently served HTTP 200 through native DNS at `http://raymond.test` on port 80 while Docker/Traefik remained reachable separately on localhost. That local observation does not replace the full disposable-runner acceptance suite.

`raymond logs` follows the daemon's log file, including live access records after upgrading the managed binary. The initial absent-service launchctl probe is silent; a real bootstrap failure is still returned. Use `raymond status` for the actual launchd state rather than interpreting a pre-start probe as service failure.
