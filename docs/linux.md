# Linux

v0.1's integration targets distributions with **both systemd-resolved and systemd-networkd already active**. The existing `/etc/resolv.conf` must point to `/run/systemd/resolve/stub-resolv.conf`. NetworkManager-only, non-systemd and container environments fail closed. Raymond never rewrites `/etc/resolv.conf` or global resolved settings.

A dedicated networkd dummy interface `raymond0` uses a reserved `192.0.2.42/32` TEST-NET address to keep systemd-resolved's DNS scope active, plus `127.0.0.43/32` for the DNS socket. The TEST-NET address is never a listening address or proxy target. Address collisions and existing interface names are refused. An owned `.link` rule persists the kernel interface alias used to verify cleanup ownership. The interface carries only route-only DNS domains, with `DNSDefaultRoute=no`. Native systemd-networkd configures resolved per-link; DNS points at `127.0.0.43:53`. Unrelated link DNS and systemd drop-ins remain untouched. Existing interface/address assignments, overlapping DNS scopes on another interface, or existing configuration resources are conflicts. Installation waits for the dedicated interface and verifies the exact DNS server, route-only domains and disabled default routing through resolvectl; unexpected state retains the recovery journal and fails closed. Native packaged lifecycle and offline-runtime acceptance passes on Ubuntu 24.04/amd64. The development container itself cannot run systemd, so validation runs on disposable real OS runners.

Use the explicit [installation walkthrough](installation.md) and [README bootstrap commands](../README.md#install-and-enable-os-integration). The reviewed bootstrap binary is copied to `/var/lib/raymond-bootstrap/raymond`; the managed systemd binary is `/usr/libexec/raymond/raymond`. Both paths must have trusted root-owned ancestors.

Install refuses existing unrelated files. An identical reinstall is a no-op; changed config or binary requires stop, uninstall and reinstall from the edited source YAML. Retain your source configuration. The installed config is `/etc/raymond/config.yaml`, root-owned, mode 0644; it must not contain secrets. The systemd service runs with DynamicUser and only CAP_NET_BIND_SERVICE. It has no network-administration capability.

The ownership journal at `/var/lib/raymond/state.json` records file hashes before publishing resources atomically. Interrupted setup retains that journal for explicit rollback. Uninstall refuses modified files and unproven interface ownership. Do not delete the journal manually. Empty installation directories and system journal logs may remain; unrelated files are preserved. Administrator repair is required if an operator edits installed resources: restore the recorded content before uninstalling. Native tests verify systemd crash recovery, controlled restart, and recovery after deleting the owned interface while stopped. A full machine power-cycle is not part of hosted-runner acceptance. NetworkManager-only and other distributions remain outside the validated integration matrix.
